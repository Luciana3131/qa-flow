🎯 Sobre o Sistema

O QA Flow é um sistema de gestão de QA criado para centralizar casos de teste, bugs, histórias/requisitos, evidências e relatórios em um único lugar.

✨ O que ele faz

  • 📋 Casos de Teste — cadastra, organiza, executa e acompanha cada teste
  • 🐞 Bugs — reporta com severidade, prioridade, reteste e vínculos
  • 📖 Histórias — rastreabilidade entre requisito e teste
  • 📎 Evidências — anexa fotos e vídeos em cada caso/bug
  • 📊 Relatórios — gera visão diária, semanal, mensal e anual
  • 💾 Backup — salva tudo num arquivo .zip com 1 clique
  • 📁 Multi-projeto — trabalha em vários projetos ao mesmo tempo

🚀 Como funciona por baixo

  • Roda direto no navegador — sem instalar nada
  • Funciona offline — depois de abrir a 1ª vez
  • Salva dados no navegador (localStorage + IndexedDB)
  • Nenhum dado sai do seu PC — tudo é local
  • Sem login, sem nuvem, sem servidor
⚠️ Importante: Como os dados ficam no navegador, se você limpar o cache ou trocar de PC, perde tudo. Por isso o backup é essencial — faz todo dia ou pelo menos toda semana.

🚀 Primeiros Passos

Se está usando o sistema pela primeira vez, siga este passo a passo:

1. Criar um projeto

  1. No topo da tela, clique em ➕ Novo Projeto
  2. Dê um nome (ex: "Sistema X — QA")
  3. Escolha "Começar vazio"
  4. Clique em ✅ Criar Projeto

2. Criar uma história (opcional)

Se seu projeto tem user stories, cadastre primeiro:

  1. Vá na aba 📖 Histórias
  2. Clique em ➕ Nova História
  3. Preencha ID (US-001), título e descrição
  4. Salve

3. Criar seu primeiro caso de teste

  1. Vá na aba 📋 Casos de Teste
  2. Clique em ➕ Novo Caso
  3. Preencha: ID, Funcionalidade, Título, Passos, Resultado Esperado
  4. Opcional: selecione uma História, adicione evidências
  5. Clique em 💾 Salvar

4. Executar o teste

Depois de rodar o teste, volte no caso e mude o status para:

  • ✅ Passou — funcionou conforme esperado
  • ❌ Falhou — apresentou problema
  • ⚠️ Bloqueado — não foi possível testar

5. Se falhou, abra um bug

  1. Vá na aba 🐞 Bugs
  2. Clique em ➕ Novo Bug
  3. Vincule ao caso de teste que encontrou o problema
  4. Descreva os passos para reproduzir
  5. Anexe evidências (print/vídeo)
  6. Salve

6. Faça backup

No fim do dia, clique em 💾 Fazer Backup (.zip) no topo. Salve o arquivo num lugar seguro.

✅ Pronto! Você já sabe o básico. As outras abas explicam cada recurso em detalhe.

📋 Casos de Teste

Criar um caso

  1. Clique em ➕ Novo Caso
  2. O ID é preenchido automaticamente (CT-001, CT-002...)
  3. Preencha os campos obrigatórios (*)
  4. Clique em 💾 Salvar

Campos do formulário

CampoDescrição
ID *Identificador único (ex: CT-001)
Funcionalidade *Área testada (ex: Login, Cadastro)
Título *Resumo curto do teste
HistóriaRequisito/User Story vinculada (opcional)
Pré-condiçõesO que precisa estar pronto antes
Passos *Passo a passo numerado
Resultado Esperado *O que deve acontecer
Resultado ObtidoO que aconteceu de fato
ComentárioAnotações, dúvidas, links
Status *Passou, Falhou, Bloqueado...
Prioridade *Alta, Média ou Baixa
EvidênciasFotos/vídeos (até 50MB cada)

Visualizar um caso

Clique em qualquer parte da linha na tabela (menos nos botões). Abre um modal somente leitura com tudo que foi preenchido.

Editar um caso

Clique no botão ✏️ na coluna Ações.

Excluir um caso

Clique no botão 🗑️. Pede confirmação.

Filtrar e buscar

  • Busca — por ID, título, funcionalidade, história
  • Status — mostra só os com determinado status
  • Prioridade — Alta, Média ou Baixa
  • História — casos de uma história específica

🐞 Bugs

Reportar um bug

  1. Clique em ➕ Novo Bug
  2. Preencha o ID (automático: BUG-001)
  3. Vincule ao Caso de Teste que encontrou o problema
  4. Defina Severidade (impacto técnico) e Prioridade (urgência de correção)
  5. Descreva Passos para Reproduzir
  6. Preencha Resultado Esperado e Resultado Atual
  7. Anexe evidências (print/vídeo)
  8. Clique em 💾 Salvar

Severidade vs. Prioridade

TermoSignificado
SeveridadeImpacto técnico do bug (quanto ele quebra)
PrioridadeUrgência de correção (quando corrigir)

Um bug pode ter severidade alta mas prioridade baixa (ex: bug crítico em tela pouco usada).

Reteste

Quando o dev diz que corrigiu, você precisa retestar:

  1. Abra o bug para editar
  2. Vá na seção 🔄 Reteste
  3. Selecione o Caso de Teste reexecutado (já vem pré-preenchido)
  4. Escolha o resultado:
    • ✅ Passou — bug corrigido (muda status para Fechado)
    • ❌ Falhou — bug persiste (muda status para Reaberto)
  5. Adicione observação e evidência do reteste
  6. Clique em ✅ Registrar reteste
💡 Dica: o reteste fica registrado como histórico. Você vê a linha do tempo completa — quantas vezes retestou, quando e qual foi o resultado.

Vínculos entre bugs

Use quando dois bugs se relacionam:

  • Duplicado de — é o mesmo problema
  • Bloqueia — este bug impede outro
  • Bloqueado por — depende de outro
  • Relacionado a — ligação genérica

📖 Histórias / Requisitos

O que são

São os requisitos ou user stories do projeto. Cada caso de teste deve estar vinculado a uma história para dar rastreabilidade.

Cadastrar uma história

  1. Vá na aba 📖 Histórias
  2. Clique em ➕ Nova História
  3. Preencha ID (US-001), título e descrição
  4. Salve

Atalho: criar direto ao cadastrar caso

No campo História do caso de teste, se você digitar um ID que ainda não existe, o sistema cria automaticamente.

Exemplo: digite US-005 — Cadastro de usuário e o sistema cria a história com esse ID e título.

Ver casos vinculados

Na aba Histórias, cada card mostra: 🎯 X caso(s) — quantos casos estão vinculados. Clique no card para ver a lista.

📊 Relatórios

Tipos de período

  • 📅 Diário — hoje
  • 📆 Semanal — semana atual (segunda a domingo)
  • 🗓️ Mensal — mês atual
  • 📊 Anual — ano atual
  • ⚙️ Personalizado — você escolhe as datas

O que o relatório mostra

  • Total de casos, passou, falhou, bloqueado
  • Taxa de sucesso (%)
  • Total de bugs + críticos + alta severidade
  • Densidade de bugs (bugs por caso)
  • Total de retestes e resultado
  • Gráficos de barras
  • Tabela detalhada de casos e bugs

Imprimir relatório

  • 🖨️ Imprimir Simples — só cards, gráficos e tabelas
  • 🖨️ Imprimir Detalhado — inclui fotos das evidências também
💡 Dica: na janela de impressão, escolha "Salvar como PDF" para guardar o relatório em arquivo.

💾 Backup e Restauração

⚠️ O backup é a parte mais importante do sistema. Sem ele, se você limpar o navegador ou trocar de PC, perde tudo.

Como fazer backup

  1. Clique em 💾 Fazer Backup (.zip) no topo
  2. Aguarde o processamento (barra de progresso aparece)
  3. Baixa um arquivo qa-flow-backup-AAAA-MM-DD.zip
  4. Guarde em local seguro: Google Drive, OneDrive, HD externo, pendrive

O que vai no backup

  • dados.json — todos os casos, bugs, histórias, retestes e vínculos
  • Pasta por ID — CT-001/, BUG-002/ com todas as fotos e vídeos
  • _mapa-evidencias.json — organiza os arquivos
  • LEIA-ME.txt — instruções

Como restaurar

  1. Clique em 📥 Restaurar Backup
  2. Selecione o arquivo .zip
  3. Confirme (⚠️ sobrescreve tudo que tem agora)
  4. Aguarde — a página recarrega

Quando fazer backup

FrequênciaQuando
Diário (recomendado)Fim do expediente
Semanal (mínimo)Sexta ou domingo
ObrigatórioAntes de limpar cache, trocar PC, atualizar o qa.html
✅ Lembrete: o sistema mostra no topo quando foi o último backup. Se passar de 3 dias, o aviso fica amarelo. De 7 dias, vermelho.

❓ Perguntas Frequentes

O sistema precisa de internet?

Só na primeira vez que abre (pra carregar a biblioteca de ZIP). Depois funciona 100% offline.

Posso usar em vários projetos ao mesmo tempo?

Sim! Cada projeto é isolado. Um caso do projeto A não aparece no projeto B. Use o seletor 📁 Projeto no topo.

Como trocar de PC sem perder dados?

  1. No PC antigo: faça backup (.zip)
  2. Leve o .zip e o qa.html no pendrive
  3. No PC novo: abra o qa.html e faça Restaurar Backup

O sistema perde dados se eu fechar o navegador?

Não. Tudo fica salvo automaticamente. Só perde se limpar o cache ou desinstalar o navegador.

Posso ter o mesmo sistema em 2 computadores?

Sim, mas cada um tem seus próprios dados. Para sincronizar, use backup/restauração.

Quantos casos posso ter?

Milhares. O limite é o espaço do navegador (geralmente ~50% do disco livre).

E se eu passar de 50MB por evidência?

O sistema bloqueia. Recomendo comprimir vídeos antes de subir (720p, até 1 minuto).

Como compartilhar com o time?

  • Envie o qa.html por e-mail/pendrive
  • Ou hospede no GitHub Pages (grátis) e mande o link
  • Ou imprima o relatório em PDF e compartilhe

Posso exportar pra Excel?

Sim! Use 📥 Exportar CSV e abra no Excel ou Google Sheets.

Como personalizar as cores?

Precisa editar o código no <style>. Procure por #3498db (azul principal) e troque pela cor desejada.

Posso adicionar novos status?

Sim, mas precisa editar o HTML (procure <option value="Passou">) e o CSS (adicione o estilo do novo badge).

🆘 Solução de Problemas

"Perdi todos os meus dados!"

  1. Restaure o último backup (📥 Restaurar Backup)
  2. Se não tiver backup, os dados não têm como voltar
  3. Lição: faça backup diário

"O backup travou ou não baixou"

  • Verifique se está conectado à internet (1ª vez)
  • Se tiver muitas evidências, pode demorar 30s-1min
  • Tente novamente em aba anônima
  • Se persistir, exporte CSV como plano B

"A janela de impressão abre em branco"

  • Permita pop-ups pro arquivo (barra de endereço)
  • No Chrome: ícone de pop-up bloqueado → "Sempre permitir"
  • Tente de novo

"Uma foto/vídeo não sobe"

  • Verifique se é menor que 50MB
  • Formatos aceitos: PNG, JPG, WEBP, MP4, WebM
  • Comprima o arquivo antes (video → 720p, 1 min)

"Fiz backup mas não vejo os arquivos dentro do .zip"

  • Extraia o .zip (clique com botão direito → Extrair)
  • Abra a pasta qa-flow-backup-AAAA-MM-DD/
  • Lá dentro tem dados.json e pastas por ID

"O sistema está lento"

  • Feche abas do navegador que não está usando
  • Se tiver muitas evidências, o IndexedDB pode pesar
  • Considere fazer backup + limpar evidências antigas

"Esqueci a última alteração que fiz"

  • Não tem como "desfazer" no sistema
  • Solução: restaure um backup anterior
  • Lição: faça backup antes de mudanças grandes

"Não consigo abrir o arquivo .html"

  • Clique com botão direito → Abrir com → Chrome
  • Se salvar como .html.txt, renomeie tirando o .txt
  • No Windows: ative "Extensões de nomes de arquivos" pra ver

"O navegador bloqueou a janela de impressão"

  1. Olhe a barra de endereço — tem um ícone de pop-up bloqueado
  2. Clique nele → "Sempre permitir pop-ups deste site"
  3. Tente imprimir de novo
